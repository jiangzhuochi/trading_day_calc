# 交易日历数据契约

本文说明内置快照、用户缓存和联网更新共同遵守的数据约束。代码以严格校验为准：任何一项不满足时拒绝加载或更新，不推测、不填补数据。

## JSON 结构

```json
{
  "schema_version": 1,
  "market": "CN_A_SHARE",
  "coverage_start": "1990-12-19",
  "coverage_end": "2026-12-31",
  "generated_at": "2026-08-15",
  "session_count": 8797,
  "sources": [
    {
      "year": 2026,
      "sse": "https://www.sse.com.cn/...",
      "szse": "https://www.szse.cn/..."
    }
  ],
  "sessions": ["1990-12-19", "1990-12-20"]
}
```

## 加载校验

日历只有同时满足下列条件才可进入查询层：

- `schema_version` 和 `market` 必须是当前支持的固定值；
- 日期必须是 ISO `YYYY-MM-DD`，覆盖起日不得晚于末日；
- `sessions` 非空、严格递增、无重复、没有周六或周日；
- 首个交易日等于 `coverage_start`，最后一个交易日不超过 `coverage_end`；
- `session_count` 必须与实际条数一致；
- 来源年份严格递增且不重复；
- 上交所、深交所来源必须分别是对应官方域名的 HTTPS URL。

用户缓存还必须覆盖至少与包内快照相同的范围，并与包内已发布历史完全一致。快照生成当年允许后续官方公告纠正；更早年份不能被缓存改写。

## 联网更新流程

每个目标年份依次执行：

1. 不使用环境变量或系统代理，直接连接沪深交易所官网；
2. 从沪深交易所的官方休市公告列表发现年度公告；
3. 限定官方 HTTPS 域名并限制响应体大小为 2 MiB；
4. 分别解析两份公告中的节假日休市区间；
5. 以自然工作日为基础剔除休市日期，得到年度交易日；
6. 要求沪深两份年度结果完全一致，否则拒绝更新；
7. 合并旧日历并重新执行全部 JSON 完整性校验；
8. 在缓存目录写临时文件、刷新到磁盘，再用原子替换提交。

年度更新遇到可重试错误时会重试一次。任一年度失败，实例内状态和旧缓存均保持不变。

## 来源与边界

包内 `calendar.json` 记录了 2022—2026 年沪深交易所年度休市公告。1990-12-19 至 2021-12-31 来自原项目内置历史快照；迁移时逐日比对了原有 7,586 个交易日，未改变历史日期。

本项目计算的是上海、深圳证券交易所统一 A 股日历，不处理单只证券停牌、港股通、期货、债券银行间市场或临时交易安排。交易所后续发布临时公告时，应重新核验并更新目标年份。

## 维护步骤

发布新年度数据前：

1. 执行 `python -m trading_day_calc refresh --through-year YYYY --force --json`；
2. 检查输出中的覆盖范围、交易日数量和两条官方来源 URL；
3. 运行 Ruff 格式化、Pyright、完整测试和性能基准；
4. 将验证后的缓存内容同步到包内 `calendar.json`；
5. 构建 wheel，并确认其中包含 `calendar.json` 和 `py.typed`；
6. 在干净环境安装 wheel，验证导入、查询和 `status --json`。

若交易所网站出现 TLS、限流、验证码、页面结构变化或来源不一致，应停止发布并保留上一份已确认快照；不得使用空列表或单一来源替代双源核验。
